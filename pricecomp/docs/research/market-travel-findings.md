# Marketplace and travel interface research

Research date: 2026-09-28. Official documentation only. “Unverified” means no current official publisher/API documentation adequate to establish access was found in this review; it is not a claim that a brand is shut down.

The inventory has 16 rows: 8 marketplace candidates and 8 travel capability/provider rows. ## Marketplace findings

Amazon now documents Creators API, a REST catalog interface (SearchItems/GetItems/GetVariations/GetBrowseNodes) with JSON requests and bearer authentication. Access requires Associates enrollment for each target locale, API registration, and at least ten qualifying sales in the previous 30 days. Use the marketplace endpoint and that marketplace’s tracking tag; category/search indices, language, and currency are localized. Current locale matrix and regional token endpoints are in the official [marketplace reference](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/concepts/common-request-headers-and-parameters) and [cURL guide](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/get-started/using-curl). Cache rules require care: the API guide gives one hour for offers and one day for other resources, while the Associates license sets a 24-hour ceiling on certain cached content and imposes display/link restrictions. For implementation follow the stricter applicable license text and display timestamps when required ([best practices](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/concepts/best-programming-practices), [license/policies](https://affiliate-program.amazon.com/help/operating/policies)). This is an affiliate promotion interface, not a general-purpose cross-retailer price feed.

eBay’s current documented direct-search path is Buy Browse API, with eBay Partner Network affiliate tracking passed in `X-EBAY-C-ENDUSERCTX` to generate `itemAffiliateWebUrl`. Search supports keyword and marketplace context; affiliate commission attribution needs an ePN campaign ID. See [Browse API](https://developer.ebay.com/api-docs/buy/api-browse.html). Country/marketplace support must be taken from the Buy API marketplace support table and any endpoint-specific gaps, rather than inferred from eBay retail site availability. Public evidence reviewed did not settle cache/display terms, rate quotas, or universal country access; confirm Buy API requirements and ePN terms before building.

Kelkoo publishes a Shopping API and Reporting API request builder. Its documentation shows JWT generated from Publisher Center credentials and API request exploration; exact country matrix, field formats for downloadable feeds, rate limits, storage/display rules, and commission terms were not public in the pages reviewed. See [publisher API request guide](https://docs.kelkoogroup.com/for-publishers/quick-starts/how-to-build-a-shopping-api-or-reporting-api-request) and [Publisher Center](https://publisher.kelkoo.com/).

SHOP.COM’s official developer center documents RESTful APN product search and details with preformatted affiliate links. Its documented filters include category, brand, vendor, price, and text. A TEST publisher ID is offered for non-affiliate experimentation; production affiliate revenue share requires applying for an APN publisher ID. Formats beyond the documented web services and country/locale matrix are unverified. See [SHOP developer center](https://developers.shop.com/externalapis/).

No current official access documentation was verified for Shopello, Shopping.com, Shopzilla, or Nextag. A named shopping site, historic feed-format guide, or presence in an old network list does not prove a current publisher API. Keep those rows out of implementable connector counts until official evidence or partner credentials are supplied.

## Travel findings

Booking.com Demand API is an active REST/JSON partner service over HTTPS POST. Access requires Managed Affiliate Partner status, a contract/account-manager provisioning step, API token, and affiliate ID. Supported accommodation flows include live search, availability, redirect and booking; car rentals are also in the current API, while attractions are beta. The API reference advertises flights in its top-level inventory description, but this review did not verify a flight search collection and therefore does not count Booking as a confirmed flight provider. Hotel input includes location, check-in/out, guest/room counts, and booker country/platform; country context controls eligible rates. Public results must keep redirect-page information consistent and use the correct display price, not commissionable net amounts. See [Demand API](https://developers.booking.com/demand/docs/open-api/3.2/demand-api), [prerequisites](https://developers.booking.com/demand/docs/getting-started/prerequisites), [accommodation search](https://developers.booking.com/demand/docs/accommodations/search-for-available-properties), and [price display guide](https://developers.booking.com/demand/docs/accommodations/display-prices). Public documentation reviewed did not state a general result-cache allowance or an affiliate commission rate.

Skyscanner documents partner APIs for live flights, hotels, and car hire, plus indicative prices, content, and affiliate links. All API access requires a reviewed partner application, then an API key. Flight search requires market, locale, currency, route legs/dates, adults, with child ages/cabin optional; a create/poll session returns live results and deep links. Hotel search requires entity/location, stay dates, guest/room counts; sessions expire within 15 minutes. Car hire has its own live search. Do not invent a cache TTL for live offers; indicative flight/hotel prices are cached estimates (flight cache up to four days). The `Powered by Skyscanner` logo/link is mandatory; the partner program measures deep-link conversions and expects reasonable look-to-book. Market affects supplier/price results, while locale/currency localize. Sources: [API overview](https://developers.skyscanner.net/docs/intro), [authentication](https://developers.skyscanner.net/docs/getting-started/authentication), [flight live search](https://developers.skyscanner.net/docs/flights-live-prices/overview), [hotel live search](https://developers.skyscanner.net/docs/hotels-live-prices/overview), [usage guidelines](https://developers.skyscanner.net/docs/getting-started/usage-guidelines), [culture/region behavior](https://developers.skyscanner.net/docs/culture/overview), [hotel market price rules](https://developers.skyscanner.net/docs/hotels-live-prices/prices-breakdown).

Expedia Group’s Rapid Lodging API is a real contracted partner integration, and its official materials mention package rates/member or business rates. It requires approval and has traveler-facing launch requirements, including tax/fee display language; the property catalog needs daily refresh. Exact package-flight combination endpoint access, public affiliate deep-link/commission model, market matrix, and result retention rules remain unverified from accessible public docs. Treat Expedia as the group-level potential for Hotels.com inventory; the direct Hotels.com API is unverified. Sources: [Rapid lodging overview](https://developers.expediagroup.com/rapid/lodging), [launch requirements](https://developers.expediagroup.com/rapid/setup/launch-requirements/lodging-launch-reqs), [official partner materials](https://partner.expediagroup.com/content/dam/unified/partner/documents/brochures/talk-tech-to-me-ebook-2025_en-us.pdf).

Amadeus for Developers documents REST Self-Service flight offers and hotel search/booking services, with API tutorials and test/production environments. These are supplier/API products, not proof of an affiliate commission program. Production access, inventory scope, current quotas and commercial model need confirmation before implementation. Sources: [Self-Service tutorials](https://developers.amadeus.com/self-service/apis-docs/guides/developer-guides/resources/), [hotel APIs](https://admin.developers.amadeus.com/self-service/apis-docs/guides/developer-guides/resources/hotels/).

For additional travel, Booking.com Attractions is a concrete beta candidate; airport parking and cruises remain proposals pending official provider documentation. Other likely verticals such as transfers, activities, travel insurance, and rail should only enter the build count after a named provider’s official API/access rules are established.
